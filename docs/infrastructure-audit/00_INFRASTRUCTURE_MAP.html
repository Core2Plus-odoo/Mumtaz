Deliverable 2

Security and risk report

46 ranked risks, backed by 99 itemised code findings. These are the ones that could lose data or a client.

Critical

The repository is public

Anyone can read the server address, the port of every system, database names, a client's name and customer list, staff names, and a note that one reachable system still has a weak administrator password. Verified.

Critical

Systems reachable directly from the internet

A client's accounting system is used over an unencrypted connection on a raw port; marketing pages link to another raw port; no site blocks the database-manager page. Reported in three earlier sessions and not fixed. Reported, to confirm on the server.

Critical

No working backup

The nightly backup job has run 920 times and failed every time before doing anything. No production database, attachment store or application store has a verified copy off the server. Verified in the repository and CI history.

Critical

One customer's administrator can sign in to another customer's system

A single sign-on secret is copied into every tenant database, and the login endpoint accepts a token naming any database. Verified in code; live exposure depends on which modules are installed.

Critical

A finance API with no authentication

One of the two ZAKI back ends returns any tenant's financial snapshot by number and lets anyone rewrite its AI knowledge base. Verified in code; unknown whether it is deployed.

High

Nobody can say what code production runs

Servers track an unmerged feature branch, not main; some modules exist only on the server; 25 business rules live only inside the CRM database.

High

Weak separation between tenants

One database login for the CRM, the ERP and the client's ledger; two programs open every database on the server; one database has two programs writing to it.

High

Customer documents and financials over-exposed inside the apps

Any Faizy customer can read every family's identity documents. Any logged-in platform user can read every company's financial summary or change everyone's permissions.

High

Delivery console is open unless a setting is switched on

If it is on, fine. If not, anyone reaching it can redirect its stored CRM key and GitHub token to their own server. Which mode production uses is unverified.

High

Automation that looks alive but is not

Four of eight CI workflows cannot start, the default branch is red, the secret scan fails, and 39 of 53 Odoo modules have no tests.

What held up well

  • No API key or password found in 1,089 commits of history.
  • Jewellery modules: tested, CI-gated, carefully scoped public endpoints.
  • Faizy's server layout: own user, own database login, loopback only.
  • Pharma and Jewel deploy kits: backup first, gated steps, printed rollback.
  • All SQL parameterised; no dangerous code primitives.

What is still unknown

  • Which ports are actually open today.
  • Which database each website really opens.
  • Whether Hostinger snapshots exist.
  • Certificate and domain expiry (one note says the main domain lapsed).
  • Whether the half-built services are running.
  • Who holds server, registrar and GitHub access.
